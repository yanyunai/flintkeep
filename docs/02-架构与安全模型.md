# 02 架构与安全模型

## 技术栈

- 前端：Vue3 + Vite（可视化界面，含解锁遮罩）
- 本地服务：Node http（REST API，供界面与工具调用）；路由按关注点分模块，`server.ts` 只留生命周期与安全顺序
- 加密存储：AES-256-GCM 本地文件（跨进程写操作走文件锁）
- 主密钥：用户口令（可选再加 Secret Key）+ 随机 salt 经 PBKDF2-HMAC-SHA256 派生；落地只存 salt + verifier
- Agent 对接：内置 MCP stdio 服务（自实现 JSON-RPC 2.0，无第三方 SDK）；另有命令行 `fk`（`npm run fk`）
- 桌面壳：Electron（`electron/main.mjs` 同进程调用 `startAppServer()`；`dev:electron` / `start:electron`）

## 加密存储与主密钥

- 燧垒文件整体 AES-256-GCM 加密，明文只在内存解密。
- 主密钥 = PBKDF2-HMAC-SHA256(口令, 16 字节随机 salt, **650,000 次**) 派生 32 字节 AES-256 密钥。
- **派生参数跟着库走**：老库按 `keystore.iter` 派生（该字段缺失时按 210,000），不能无条件用新参数，否则旧库永久解不开。`GET /api/kdf` 回 `upgradeRecommended`，提示改一次口令完成升级。
- `keystore.json` 只存 `salt` / `verifier`（用派生密钥加密的已知明文）/ `iter` / `kdfVer`。
- 首次运行（无 keystore）传入口令即初始化；之后同口令解锁；无口令构造 → 锁态。
- 派生密钥仅存内存，重启需重输口令。
- **keystore 丢失不自动重建**：重建会让旧密文永远解不开，必须显式 `FLINTKEEP_FORCE_REINIT=1`。

### Secret Key（可选第二因子）

- 28 字符：26 位载荷 + 2 位 CRC16 校验，base32 去掉易混字符 `0/O/1/I`，展示为 4 组 × 7。
- 本体只落 `data/secret_key.txt`（0600），**不进 keystore、不进备份**；丢了只能靠应急包。
- 组合密钥：`masterKey = PBKDF2(口令, salt, 650k) XOR HKDF-SHA256(sk, salt, "flintkeep-sk-v1")`——口令与 SK 缺一不可。
- **verifier 恒由纯口令派生加密**：这样 unlock 才能区分「口令错」和「缺/错 SK」，否则用户会反复改口令找问题。
- 启用后 24 小时内可停用（`SK_ROLLBACK_MS`），启用时会生成并下载应急包。
- 解锁错误是三态：`NeedSecretKeyError` / `WrongSecretKeyError` / `WrongPassphraseError`。
- `unlock()` 的返回值是 `created`（是否新建库），**不是**解锁成功标志；成功与否看 `locked`。

## 锁定与请求准入

- 服务端默认锁定；`POST /api/unlock` 解锁，`POST /api/lock` 锁定（锁定也要求会话凭据，否则同机任意进程都能把库踢下线）。
- 会话凭据：解锁签发 32 字节随机 `fk_sid`（HttpOnly + SameSite=Strict），也可用头 `X-FK-Session`；锁定/重解锁即轮换。锁定后 `/api/*` 一律 401/423（GET 也在内），非接口只放行锁屏静态资源。
- 防爆破：`unlockRetryAfterMs = min(1000 × 2^(失败次数-1), 60s)`，**一次失败即进入窗口**，窗口内正确口令也回 429（重启进程清零）。
- 锁定即吊销代理令牌、SSH 与会话；`lock_state.json` 是跨进程「锁屏断开 Agent」的唯一依据。
- 锁屏默认断开 Agent（`allowLockedAccess=false`），开启后仅放行读类能力；执行类工具另受 `allowAgentExec` 控制。
- 无界面部署（MCP / CLI）从 `VAULT_PASSPHRASE`（兼容 `FK_PASSPHRASE`）自动解锁；双因子库另需 `VAULT_SECRET_KEY` / `FK_SK`（支持 `@file:`）。

## 审计模型

- 所有取密、增删改、Agent 自报操作均留痕；含 `actor`（Agent 身份，来自 MCP `clientInfo`）与 `meta`。
- **`meta` 走白名单**：调用方塞进来的字段不能改写 `ts/actor/action`，防止伪造审计。
- 保留策略：主文件超 `settings.auditMaxMB`（默认 5MB）滚动 `.1..N`，只保留 `auditKeepGenerations`（默认 3）；调小阈值不删已有文件，越界文件在下次追加时清理。
- `GET /api/audit/export` 导出原文 JSONL（含历史代，旧 → 新）。不脱敏：写入侧已挡掉敏感字段，导出再脱敏会毁掉可追溯性。
- `log_agent_action`（MCP / `POST /api/agent-action`）让 Agent 上报「做了什么」，与取密记录拼成完整审计链。

## 敏感字段脱敏

- `SECRET_FIELDS`：`sshPassword` / `keyPassphrase` / `privateKeyEnc` / `secretAccessKey` / `baotaPassword` / `baotaApiKey` / `secret` / `envEnc` / `secretId` / `secretKey`。
- 列表 / 搜索默认剥离；仅显式 `get` / `show(reveal)` / `get_server_connection` 返回明文并写审计。
- 落盘权限 0600：`vault.enc.json` / `keystore.json` / `secret_key.txt` / `access_tokens.json` / 审计与代理令牌文件；agent socket 0600、目录 0700。

## Model B 代理注入（真密钥不进 Agent 上下文）

流程：MCP / REST 签发短期令牌（`request_proxy_access` / `POST /api/proxy/issue`）→ Agent 用 `proxyBase`（独立端口，默认 8788）访问 → 代理解析令牌、注入真实凭证、转发、留 `proxy_access` 审计。

令牌本身不含任何密钥，由 `ProxyManager` 文件级（`proxy_tokens.jsonl`）存储，短 TTL，跨进程校验。

### 注入模式（proxyInject.mode）

| 模式 | 说明 |
|---|---|
| `header` | 注入 `Authorization: Bearer <secret>`，或自定义头名（如 `X-API-Key`） |
| `basic` | 注入 `Authorization: Basic base64(user:secret)` |
| `baota` | 宝塔 API 签名（`request_time` + `request_token = md5(md5(token)+time)`） |
| `aws` | AWS SigV4 签名写入 Authorization 头 |
| `aliyun` | 阿里云 RPC HMAC-SHA1 写入 query 的 `Signature` |
| `tencent` | 腾讯云 API 3.0 TC3-HMAC-SHA256：签 `content-type;host`，写 `Authorization` + `X-TC-Timestamp`；资产的「云服务」填服务名（`cvm` / `cdn` / `dnspod` / `vpc`…） |

- 云厂商签名在代理端用存储的 AccessKey / Secret 计算，Agent 全程不见密钥。
- 签名必须在**转发头定稿之后**计算：调用方带来的 `content-type` 会进转发头，腾讯云逐字节比对规范请求，先签名后拼头会直接 `AuthFailure.SignatureFailure`。AWS 的 SigV4 同样按最终头计算。
- `tencent` 模式缺 SecretId / SecretKey / `cloudService` 时直接 400 并指出缺哪项，不把未签名请求发给上游；旧字段 `secretId` / `secretKey` 作回退。
- 已验证：AWS SigV4 派生 + 签名对齐官方向量；阿里云 HMAC 自校验一致；腾讯云 TC3 与真实转发请求逐字节复算一致（含 content-type / query / body）；全链路注入测试通过。

## SSH 会话代理（Model B，已实现）

**定义**：本地"堡垒机 / 跳板"。Agent 只用短期令牌连本地代理；真实私钥 / 密码由燧垒服务端用 `ssh2` 注入到对目标服务器的真实 SSH 连接里，Agent 全程只持令牌，真密钥永不进上下文。

**实现（2026-10-09）**：

1. `src/core/sshproxy.ts`：`SshProxyServer` 监听 `127.0.0.1:SSH_PROXY_PORT`（默认 8789）；host key 落盘 `data/ssh_host_key.pem`。
2. MCP `request_ssh_access` / REST `POST /api/ssh/issue` → `{proxyHost, proxyPort, token, targetHint, ...}`。
3. Agent：`ssh -o StrictHostKeyChecking=accept-new -p 8789 <token>@127.0.0.1`（token 作 username）。
4. 校验令牌 → `resolveSshTarget`（密码或关联 `ssh_key`）→ `ssh2.Client` 拨目标 → 透传 shell / exec / pty。
5. 连接写 `proxy_access`（path=`ssh-session`）审计；会话收尾再写一条 `ssh_exec`（exec）或 `ssh_session`（交互 shell），含脱敏后的命令摘要、时长与成败，失败带原因。
6. `server.ts` 解锁后与 HTTP 代理一并启动。

**未做增强**：SFTP 通道透传、命令级摘要、会话录屏（见 05 / 06）。

## 本地 SSH agent（`src/core/ssh-agent.ts`）

- 把 `ssh_key` 资产的私钥做成标准 agent：`ssh` / `git` / `scp` 直接可用，私钥不出本进程。
- **只读视图**：只实现 `REQUEST_IDENTITIES` / `SIGN_REQUEST`；`ADD/REMOVE/LOCK/EXTENSION` 一律 `SSH_AGENT_FAILURE`——密钥来源只有保险库，agent 不提供写入面。
- 每次签名先过锁屏策略（与 MCP/REST 同一套 `lock_state.json` + `allowLockedAccess`），允许与拒绝都写审计（`agent_sign` / `agent_sign_denied` / `agent_key_invalid`）。
- socket 落数据目录（0600，目录 0700，路径 ≤ 100 字符）；陈旧 socket 自动清理；两个 agent 抢同一路径时发起方报错。
- 开关 `settings.sshAgent`（默认关）：解锁即启动、锁定即停止、切换即时生效。入口：`fk agent` / `fk agent env` / `fk agent status`，设置页卡片给出 socket 与导出命令。

## 访问令牌（服务账号，`src/core/access-token.ts`）

- `fksa_` 前缀 32 字节随机令牌，**只存 SHA-256 与前 12 位前缀**；scope（`assets` / `types`，必须非空）+ caps（`proxy` / `ssh`）+ 1–365 天有效期。
- 撤销立即生效；桌面端管理（`/api/access-tokens`，要求会话），创建响应只回一次明文。
- 换发（`POST /api/access-token/exchange`）免会话但**要求已解锁**：锁定态回 423。
- Agent 用令牌模式启动（`FK_TOKEN` / `VAULT_TOKEN`）：只下发 `find/show/connect` 三个工具，且不解密任何密文——能力边界与令牌 scope 一致。

## CLI（`fk`，`src/core/cli.ts`）

- 子命令：`status` / `list` / `show` / `connect` / `env` / `inject` / `agent` / `token`。
- 凭据只走环境变量或 TTY：`FK_PASSPHRASE`、`FK_SK`（支持 `@file:`）、`FK_TOKEN`、`FK_DATA_DIR`、`FK_BASE`。
- 退出码：`0` 成功、`1` 运行错误、`2` 用法错误、`3` 凭据缺失或错误、`4` 目标未找到或歧义。
- `show` 默认脱敏，`--reveal` 走 `vault.get` 并写审计；`connect` 只给堡垒命令或代理令牌；`inject` 做占位符替换（`{{fk:目标.字段}}`），**替换是原子的**：任一占位符失败则整体不输出，stdout 与报错都不会漏出已取到的值。

## REST 分层与请求边界

请求从进入 `createHttpServer` 到业务处理的**顺序本身是安全语义**，不要重排：

1. Host 必须是回环（`127.0.0.1` / `localhost` / `[::1]`），否则 403——DNS rebinding 防护。
2. 免会话区（锁定态也要能读）：`/api/locked`、`/api/kdf`、`/api/sk`、`/api/settings` 读、`/api/ssh-agent` 元数据、`/api/mcp-setup`、`/api/myprojects` 读、`/api/system/stats`、令牌换发。
3. 解锁门 + CSRF：`/api/*` 非 GET 必须带会话凭据（或命中 `allowLockedAccess` 的显式放行），跨站请求拒绝。这段落在 `security-routes.ts` 入口，先于所有业务分支。
4. 业务路由模块（assets / ops / whitelist / assistant / ai-usage），按固定顺序短路。

其他边界：

- `readBody` 上限 16MB，超限按 4xx 回；静态资源做路径边界校验（不允许 `..` 越出 dist）。
- 跨进程写操作走 `file-lock.ts`：`O_EXCL` 建锁、同进程重入计数、stale 15s、最多等 3s，超时抛 `FileLockTimeoutError` 并带持锁 pid。
- Electron：`sandbox: true` / `contextIsolation: true` / `nodeIntegration: false`；拒绝新窗口与外部导航，权限请求一律拒绝；页面带 CSP，不执行外部脚本。
- 不拼 shell：外部命令用参数数组直接执行，不用 `shell: true`。

## IP 白名单（自动更新）

家庭宽带的公网 IP 会变，云上放行规则得跟着改。流程：`ipdetect` 探测当前 IP → 与云上现有条目比对 → **IP 没变就不调 API**（避免打满 QPS 被限流）→ 变了才整体替换并写审计。

| 厂商 | 更新对象 | API |
|---|---|---|
| 阿里云 | ECS 前缀列表 | `DescribePrefixLists` / `ModifyPrefixList`（RPC HMAC-SHA1，复用 `proxy.ts`） |
| 腾讯云 | VPC **IP 地址模板** | `DescribeAddressTemplates` / `ModifyAddressTemplateAttribute`（`AddressesExtra` 整体替换） |

腾讯云侧安全组规则只是**引用**模板，改模板即自动放行，所以「安全组 ID」只是备注。地域 / 模板 ID 由页面实时下拉获取，不用手填。

**坑（已修）**：`DescribeRegions` 是全局接口，但腾讯云网关要求 `X-TC-Region` 头**非空**，传空串会被拒（`MissingParameter: Region`）。现在有 `ap-guangzhou` 兜底。

## 模型用量（AI 用量监控）

三类数据源各司其职：**余额 / 消费 / 资源包**走阿里云 BssOpenApi；**模型清单**走 DashScope `/api/v1/models`；**免费额度**只能走百炼官方 CLI `bl usage free`（模型清单 API 不含额度字段，官方也没有公开额度 API）。

- **不做花钱探测**：探测要真实调模型、消耗额度且触发风控，已关闭；刷新默认只读取数接口，CLI 侧靠定时 + 限频（距上次 <60s 返回 429）。
- **多账号靠 `--config`**：CLI 单登录态 + 多 Profile，一个阿里云账号对应一个 Profile，绑定到云账号后按 `bl --config <profile>` 取数。
- **归属严格 + 失败不清空**：未绑定就显示空（不把 A 账号额度显示到 B 账号）；取数失败保留上次数据并标记 `quotaStale`，同时把 CLI 错误转成人话（如控制台令牌失效 → 提示 `bl auth login --console`）。
- 凭据同样只从燧垒取、内存中使用后即弃。
- 多账号刷新默认 3 路并发（探测串行）；配置与价目写文件走 `file-lock`，绑定关系用锁内重读合并。

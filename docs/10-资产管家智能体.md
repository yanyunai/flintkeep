# 10 · 资产管家智能体（AI 助手）

> 2026-11-06 立项并交付 v1。定位：应用内的资产管理智能体——口语指令直接操作燧垒数据。
> 名字：对外「资产管家」，页面标题同。

## 一、为什么做

- 原「AI 助手」= 原作者工作台的聊天框：上下文注入好、13 个模板，但**没有工具调用**，只能"说"不能"做"（顾问级）。
- 用户目标：口语式指令（记东西/加账号/加资产/加备忘录/改 IP/建关联）→ 直接落库，以后不想手动操作；删除类要人工确认。
- 外部 Agent（ZCode/cursor）已经能通过 MCP 的 15 个工具操作资产库——本智能体把同样的能力搬进应用，两边共用燧垒数据层。

## 二、技术选型（2026-11-05 调研）

- **Vercel AI SDK（`ai` v7）+ `@ai-sdk/openai-compatible` + `zod` v4**：模型无关（DeepSeek/百炼/火山/Ollama 等 OpenAI 兼容接口都行），TS 生态工具调用的事实标准。
- 未选 Mastra（引入独立存储层）/ LangChain（过重）/ mem0（记忆要出本机或加 Docker+PG，与密钥管理的隐私定位冲突）。
- **记忆方案**：燧垒加密集合 `ai_memory`，工具 remember/recall，关键词检索、无向量库——数据不出本机、进每日备份。

## 三、架构

```
用户口语 → 自写「AI 助手」页（Vue）
  → POST /api/assistant/chat（server.ts）
    → src/core/assistant.ts：generateText + 9 个工具（stopWhen: stepCountIs(6)）
      → Vault 直接操作（add/update/remove/link/probe），全程走既有审计+恢复点
  → 回执卡片（✓ 已执行 / ⚠ 待确认）+ 文字回复
```

### 工具集（9 个）
| 工具 | 能力 |
|---|---|
| add_asset | 新增任意类型资产（fields 为 JSON），可顺带 linkTo 关联 |
| update_asset | 修改资产字段 |
| delete_asset | 删除——**两段确认**：返回 needsConfirm+cid，用户点「确认删除」才真删 |
| search_assets / get_asset | 搜索/详情（秘密字段一律打码，模型上下文永不接触秘密明文） |
| link_assets | 两资产建立关联（角色自动推断） |
| remember / recall | 长期记忆写入/检索（加密集合 ai_memory，上限 200 条） |
| probe_server | TCP 探测服务器连通性 |

### 数据归属（全部加密、进每日备份）
- `ai_conf`：模型配置（base/model/key/name）
- `ai_sessions`：会话历史（最近 30 个会话、每个 40 条消息）
- `ai_memory`：长期记忆（200 条）
- 待确认删除：进程内存 Map，10 分钟 TTL

## 四、页面（自写，不含 vendor 代码）

- 新会话落地页：居中问候「资产管家，我帮你」+ 分类 tab（常用/资产/服务器/参谋）+ 预选指令胶囊（点击预填）+ 大输入框（模型选择+发送）
- 对话中：干净对话流 + 工具回执卡（✓/⚠）+ 底部输入框；删除确认卡片带「确认删除/取消」
- 设计语言沿用应用：暖灰底/白卡/发丝线/黑主按钮，无渐变无 AI 味；深浅色都适配
- vendor 旧 AI 页保留为「旧版助理(vendor)」入口（版权净化完成前不删代码）

- GET `/api/assistant/sessions`、GET `/api/assistant/session?id=`
- POST `/api/assistant/chat` {sessionId, text}
- POST `/api/assistant/confirm` {cid, approve}

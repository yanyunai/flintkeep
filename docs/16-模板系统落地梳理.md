# 16 · 模板系统落地梳理（黑曜 · 深/浅）

> 前置：`design/system/GUIDE.md`（K3 产出）、`docs/15-UI重设与样式架构方案.md`
> 决策：**第一版只做「黑曜」一套模板的深色与浅色**，但必须按模板机制落地——页面不写颜色、不写模板分支，换皮肤只改一个属性值。
> 不做：底部切换条（demo 用）、中英文切换（下一阶段）、纸墨模板接入入口（CSS 留在仓库，先不暴露）。

---

## 一、必须解决的第一个问题：样式作用域隔离

现有 `App.vue` 与 `base.css` 有三处硬冲突，直接全局引入会把现有界面弄坏：

| 冲突 | 现有 | base.css | 后果 |
|---|---|---|---|
| 根类名 | `<div class="app">` | `.app { height:100vh; background:var(--bg) }` | 现有页面被套上 100vh 与另一套底色 |
| 全局重置 | 依赖浏览器默认 `button` 样式 | `button{border:0;background:none;padding:0}` · `body{overflow:hidden}` | 所有按钮变裸样式、页面不能滚 |
| Token 名 | `--bg --text --accent --line?` | `--bg --panel --text --line --accent --r-*` | 同名不同义，互相覆盖 |

**方案：`#mgui` 作用域前缀**

- base.css / tpl-obsidian.css 在构建期由脚本重写成 `#mgui` 前缀版本，产物放 `src/renderer/styles/ui/`
- token 定义挂在 `#mgui` 上（不进 `:root`），现有页面完全拿不到
- 新界面统一渲染在 `<div id="mgui" data-template="obs" data-theme="dark">` 之内
- 老页面继续用现有 scoped 样式，两边井水不犯河水
- 全站迁移完成后，把挂载点从 `#mgui` 提升到 `<html>`，只改一行

这样「以模板形式」的要求被满足：**皮肤=变量赋值，页面=语义类，切换=改 `data-template` / `data-theme`**。

## 二、文件落位

```
src/renderer/styles/
├── ui/
│   ├── base.css          ← 由 design/system/base.css 生成（#mgui 作用域）
│   ├── tpl-obsidian.css  ← 由 design/system/tpl-obsidian.css 生成
│   └── README.md         ← 说明「不要手改，改源文件后重跑脚本」
scripts/build-ui-scope.mjs ← 生成脚本（幂等）
design/system/            ← 唯一可手改的源文件
```

引入顺序（`main.ts` 里一次）：

```ts
import './styles/ui/base.css';
import './styles/ui/tpl-obsidian.css';
```

规则：**任何人不得直接改 `src/renderer/styles/ui/*.css`**，改 `design/system/` 源文件后重跑脚本。

## 三、外观设置

- 存储：`settings` 集合里的 `appearance: { template: 'obs', theme: 'dark' }`（跟其它设置一样走 `/api/collections`，跨设备一致）
- 兜底：`localStorage.mgui.appearance`，用于首屏（避免读接口期间的闪烁）
- 挂载：`#mgui` 元素的 `data-template` / `data-theme` 由 Vue 响应式绑定
- 入口：设置页新增「外观」卡片 —— 模板（黑曜，暂时只有一项）+ 主题（深色 / 浅色 / 跟随系统）
- 默认：**黑曜 · 深色**

## 五、需要新增的语义组件（K3 的 base.css 里没有）

| 组件 | 用途 | 关键点 |
|---|---|---|
| `.chart-card` | 模型用量、收支 | 纯 CSS/SVG，不引图表库 |
| `.timeline` | 审计日志 | 左侧竖线 + 时间点，深色下不能糊 |
| `.code-card` | MCP 接入 | 等宽、可复制、长行横向滚动 |
| `.settings-grid` | 设置页 | 两列分区，窄屏塌成一列 |
| `.msg` / `.msg-body` | AI 助手 | 用户/助手/工具三类气泡 |
| `.kanban` | 迭代任务 | 列 + 卡片，拖动下一版做 |
| `.form-grid` | 各类表单 | label + 控件 + 错误提示三件套 |

新增组件一律先入 `base.css`（用 token），再在两套皮肤里补微调；页面只引用类名。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 老页面被新 CSS 污染 | `#mgui` 作用域，先在小范围验证（见第七节） |
| 两套模板各改一遍，漏测 | 只交付黑曜；每次改 UI 固定跑「深/浅 × 主要页面」清单 |
| 迁移期两套界面并存，视觉割裂 | 侧栏加「经典/新版」标识，迁移完一页切一页，不一次性替换 |
| `App.vue` 继续膨胀 | 新页面一律独立 `.vue` 单文件，`App.vue` 只做路由分发 |
| 手改生成产物被覆盖 | `README` 写明 + 脚本幂等，避免"改了没生效"的坑 |

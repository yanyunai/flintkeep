# 01 需求与定位

## 原始诉求

用户需要一个**本地**的「基础设施凭证 + 资产清单」管理工具，核心痛点：

- 每次让 Agent（AI）连服务器 / 云，都要手动粘贴 IP、端口、账号、密码、云密钥、OSS、宝塔面板、MCP 配置等连接信息。
- 希望 Agent 通过 MCP 自行取用这些信息，用户不再手贴。
- 要能记录"哪台服务器开了哪些端口"这类资产信息。
- 必须有**可视化页面**（能看到的），而非纯命令行。
- 必须有**审计**：哪个 Agent 什么时候来取了什么、取完之后干了什么。
- 必须有**轮换提醒**：密钥多久提醒换一次。
- 采用 **AGPL-3.0-only**（2026-11-21 定案）：个人与企业内部使用不受限；闭源分发或闭源服务化需另行获得商业授权。

## 覆盖范围（资产类型）

服务器（IP / SSH 端口 / 开放端口 / 账号密码）、SSH 密钥、云账号（阿里云 / 腾讯云 / AWS）、OSS、宝塔面板、MCP 配置、通用密钥。

## 设计取向决策

- **自己写干净核心，不 fork 任何开源项目**。原因：需求比 Keygate / Teleport 的"代理 / 访问"定位更宽（还要管资产清单 + 端口），自写协议完全自由。
- **架构借鉴成熟方案的设计思路**（只读思路，不动代码）：
  - Keygate（alias + 代理 + 审计 + MCP）
  - Teleport（审计 / 会话录屏）
  - ClawVault（仪表盘 / 审计）
  - Infisical（Agent Proxy）
  - gopass（加密存储）
- **协议选择**：本项目代码采用 **AGPL-3.0-only**；「燧垒 / FlintKeep」名称与 Logo 不随代码授权。

## 两种取用模式（贯穿全程的核心取舍）

- **Model A（v1）**：明文直给 + 审计。Agent 直接拿到明文凭证，简单直接，配合审计即可。
- **Model B（v2）**：代理注入别名。Agent 只拿短期令牌 + 本地代理基址，真实密钥由代理服务端注入，永不进 Agent 上下文。更安全，是重点演进方向。

## 实现现状对齐（2026-11-25）

初始诉求里的两条主线——「Agent 自己取用」与「可视化 + 审计」——现在落成了四条取用通道，**共享同一套保险库、权限与审计**：

| 通道 | 形态 | 密钥去向 | 适用 |
|---|---|---|---|
| MCP（v2） | 9 个任务入口（`find/show/connect/manage/run_project/sync_whitelist/usage/note/backup`） | `connect` 只给堡垒命令或代理令牌 | Claude Code / Cursor 等 MCP 宿主 |
| 本地 CLI（`fk`） | 终端命令：`status/list/show/connect/env/token/inject/agent` | 明文只走 stdout/stderr 或环境变量，凭据从环境变量/TTY 读 | 脚本、CI 调试、人工排障 |
| 本地 SSH agent | `export SSH_AUTH_SOCK`，标准 ssh-agent 协议 | 私钥不出进程，签名留审计 | `ssh`/`git`/`scp`/`rsync` 日常 |
| 访问令牌（`fksa_`） | 换取单资产短期代理/SSH 凭据 | 令牌解不开整库 | 无人值守服务账号 |

与初始设计的差异（都是后来安全审查后的收敛）：

1. **Model A（明文直给）默认关闭**：`connect` 默认不给密码/私钥；`show` 默认脱敏，`--reveal` 才出明文并落审计。
2. **加密模型从「单一主口令」升级为双因子**：主口令 + Secret Key（PBKDF2 ⊕ HKDF，见 docs/设计-2026-11-25-SecretKey与应急包.md）；换机必须持应急包，单机失窃这一层不护。
3. **锁屏是硬边界**：解锁才签发会话凭据；锁定即吊销会话、断开代理与 SSH 堡垒、停止 SSH agent。
4. **执行类工具与数据权限正交**：`allowAgentExec` 默认关，Agent 不能借 MCP 在本机跑命令。

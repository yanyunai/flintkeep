# 18 国际化（中英文）方案

> 目标：全量中英文，不遗漏、不半中半英；切换语言不刷新、不重启；前后端与桌面壳共用一套字典。
> 结论先行：**自研 i18n 运行时（约 150 行）+ 分域字典 + 类型安全 + 漏翻检查脚本**，不引入 vue-i18n。

## 1. 范围（"全量"的边界）

统计口径：含中文的非注释代码行与去重文案。

| 层 | 位置 | 数量级 | 翻不翻 |
|---|---|---|---|
| L1 壳层 | `App.vue` 侧栏/顶栏/通用按钮/空状态/toast、锁屏页 | ~300 条 | 翻 |
| L2 页面 | `views/*.vue` + `MyProjects.vue` + `SettingsPanel.vue` + `McpGuide.vue` + `NocHud.vue` | ~900 条 | 翻 |
| L3 共享元数据 | `asset-types.ts`、`builtin-fields.ts`、`schema.ts`（TYPE_LABELS / LINK_ROLE_LABELS / 状态名） | ~200 条 | 翻（前后端共用） |
| L4 后端消息 | `server.ts` 48 处 `error:`、`src/core/*.ts` 34 处 `throw new Error` | ~120 条 | 翻 |
| L5 MCP | `mcp-meta.ts` 89 个 `description` + 工具返回文案 | ~100 条 | 翻（默认英文） |

| L7 桌面壳 | `electron/main.mjs` 菜单、托盘、通知、对话框 | ~40 条 | 翻 |
| — | `src/core/test.ts` 断言 | 292 行 | 不翻（测试内部） |
| — | 审计历史数据 | 库里已有中文 | 不翻（新产生的才翻） |

合计要翻约 **1,700 条**，落在 **55 个文件的 40 个左右**。

## 2. 现状（为什么不能"加个开关"了事）

- 依赖里没有 `vue-i18n`，全项目无 `t()` / `useI18n`
- 文案硬编码在模板、JS 字符串、后端返回三处
- 已有几处"中文映射表"（`auditCn` / `auditFieldCn` / `TYPE_LABELS`），它们本身就是字典，只是写死中文
- `settings.json`（明文）有 `closeAction` / `autoLockMinutes` / `agentPermission`，可以扩一个 `lang`

## 3. 架构决策

### 3.1 运行时：自研，不用 vue-i18n

理由：

1. 只有 Electron 单机，无 SSR、无路由级懒加载语言包
2. 只需要 **插值** 和 **简单复数**，`vue-i18n` 的其它能力用不上，却要 +20KB 和一套新约定
3. **后端要复用同一份字典**（`server.ts`、`src/core/*`），`vue-i18n` 是前端包，后端引不了
4. 项目已有 `appearance.ts` 的写法（`ref` + `localStorage` + `watch`），风格保持一致

### 3.2 目录

```
src/shared/i18n/
  runtime.ts      # t() / setLang() / getLang() / 插值 / 复数 / 订阅
  zh/
    common.ts     # 通用：按钮、状态、单位、空状态、分页
    shell.ts      # 侧栏、顶栏、锁屏、toast
    assets.ts     # 资产类型、分类、字段标签、列配置
    studio.ts     # 机房场景、机柜/工位/控制台
    projects.ts   # 项目、里程碑、入口
    business.ts   # 收支、任务、灵感、资料、备忘录
    ops.ts        # 白名单、模型用量、MCP、审计、设置
    errors.ts     # 后端错误 + 桌面壳
  en/             # 与 zh 同名同结构
  index.ts        # 合并字典 + MsgKey 类型导出
```

按域拆文件：单文件 1,700 条没法 review，出冲突也没法解。

### 3.3 key 规范

`域.区块.语义`，全小写，用点分层：

```
common.btn.save
shell.nav.studio
assets.type.server
assets.field.publicIp
studio.legend.running
projects.milestone.add
errors.vault.locked
```

禁止把中文当 key（`t('保存')`），否则英文排版一改就全乱。

### 3.4 类型安全

```ts
// index.ts
export const zh = { ...common, ...shell, ...assets, ... } as const;
export type MsgKey = keyof typeof zh;
export function t(key: MsgKey, vars?: Record<string, string | number>): string;
```

`t()` 只接受 `MsgKey`，写错 key 编译期就报错，不用等页面出现 `common.btn.save`。

组件里用 `const tr = useT()`（`src/renderer/ui/i18n.ts`），模板写 `{{ tr('shell.nav.assets') }}`；
`tr()` 内部读一次 `lang.value`，所以切换语言后模板自动重渲染，不需要刷新。

### 3.5 插值 / 复数 / 数字日期

```ts
t('assets.count', { n: 64 })        // zh: "{n} 项资产"  en: "{n} assets"
t('assets.count', { n: 1 })         // en 走复数：messages 里写 "{n} asset | {n} assets"
```

- 复数用 ` | ` 分隔单复数，运行时按 `Intl.PluralRules` 选
- 数字/日期/文件大小统一 `Intl.NumberFormat` / `DateTimeFormat`，语言跟着 `lang` 走，**不手写格式化**
- 时间戳展示（审计、运行动态）注意：审计里的 `formatTs` 已是本地化格式，改 `Intl` 即可

### 3.6 语言状态

```ts
// 优先级：settings.json（跨设备/重启保持） > localStorage（首屏不闪） > 系统语言（app.getLocale）
export type Lang = 'zh-CN' | 'en-US';
```

- 首屏：`localStorage.getItem('mg.lang')` 同步读，避免闪一下中文再变英文
- 切换：`setLang()` → 更新 `ref` → `document.documentElement.lang` + `localStorage` + `PUT /api/settings`
- 不刷新：所有文案走 `t()`，模板自动重渲染

### 3.7 后端怎么"说英文"

三条路，选 **B**：

| 方案 | 做法 | 评价 |
|---|---|---|
| A | 后端返回错误码，前端翻译 | 最干净，但要改 48+34 处返回结构，还要给每个错误定义码 |
| **B** | 后端读 `settings.lang`，`t()` 同一个字典 | 改动小，和前端同一套字典，天然一致 |
| C | 后端 `Accept-Language` | 桌面单用户场景没必要，MCP 调用又没有浏览器头 |

具体：`server.ts` 启动时 `setLang(settings.get().lang)`；`PUT /api/settings` 改语言时同步更新后端运行时语言。
MCP 是独立进程（stdio），读 `settings.json` 拿语言，默认 **英文**。

### 3.8 不改的部分

- **资产数据本身**（项目名、备注、客户名）—— 用户输入，不翻
- **历史审计记录** —— 库里存的是当时的中文，翻不了也不该翻
- **测试断言** `src/core/test.ts`
- **日志文件** `logs/*.log` —— 保持中文，便于你排查；也不该随语言变

## 5. 布局风险与对策

英文普遍比中文长 30–50%，这个项目有几处"卡得很死"：

| 位置 | 风险 | 对策 |
|---|---|---|
| 侧栏 212px | `模型用量` → `Model Usage` 更长；`迭代任务` → `Iteration Tasks` | 允许两行（`line-height:1.35`），必要时 EN 下加宽到 232px |
| 表单 label | `合同金额(元)` → `Contract amount (CNY)` | label 上移一行，或 `white-space: normal` |
| 表格表头 | `最后使用` → `Last used` | 表头不限宽，列宽给 `min-width` |
| 机房 SVG | `t()` 后字宽变化，`fit()` 按像素裁会提前截断 | 英文按 0.55em/字符估算已考虑；实测后再调 `fit()` 系数 |
| 按钮 | `签发 SSH 代理` → `Issue SSH proxy` | 按钮 `min-width` + `padding` 自适应，禁止写死宽度 |
| 空状态 | 中文一句话 → 英文两行 | 容器高度自适应，不写 `height` |

## 6. 质量保障

`scripts/check-i18n.mjs` 做四件事：

1. **key 对齐**：zh 与 en 的 key 集合必须完全一致（缺一个就失败，并打印路径）
2. **源码引用**：扫描 `t('...')` 字面量，检查 key 存在（防止删字典漏改代码）
3. **占位符**：同 key 两侧 `{x}` 变量集合一致（防止 `{n}` 写漏）
4. **空值**：不允许空字符串或残留中文在 en 里（可选白名单）

挂到 `package.json`：

```json
"i18n:check": "node scripts/check-i18n.mjs",
"i18n:stat":  "node scripts/check-i18n.mjs --stat"
```

`--stat` 输出各域完成度（已翻/总数），用于看 P1–P5 的进度。

另外建议：**每批做完立刻跑一次 `core:test`**（224 条断言），确保改 `TYPE_LABELS` 这类共享元数据没压坏后端。

## 7. 已确认的决策

| # | 问题 | 结论 |
|---|---|---|
| 1 | 默认语言 | **中文**；首启可改，切换后写 `settings.json`，跨重启/换设备保持 |
| 2 | MCP 工具描述 | **跟着语言切换**（中英两套字典），不写死英文 |
| 3 | 历史审计日志 | **不翻**（库里存的是当时的文本），新产生的记录跟着语言走 |
| 4 | 英文变体 | **en-US**（美式拼写、`MM/DD/YYYY`） |
| 5 | 给 Agent 的字段名 | **跟 UI 语言**，MCP 返回同时带 `key`，Agent 用 key 匹配更稳 |

### 9.2 与初始方案的三处偏差

1. **MCP 工具描述不读 TS 字典，而由前端补一层**
   `mcp-meta.ts` 的描述是给 Agent 看的长文（`project_upsert` 一条就 300+ 字）。全量双语会让工具表膨胀一倍，且 Agent 侧始终拿一份即可。
   做法：后端保留详版中文，`McpGuide.vue` 在英文界面按 `mcp.tool.<name>` 取**精简英文**（平均 12 词），中文界面继续用后端详版。判定方式 `key in zhDict`，不猜。

2. **已缓存的中文在渲染时改写，不追溯数据**
   价目摘要、额度重置说明是算好存进 `data/ai_usage/*.json` 的。`priceSummary()` / `resetText()` 在渲染时把 `入 10 / 出 30 · 百万tokens` 改写成 `In 10 / Out 30 · M tokens`，旧缓存不必等过期。
   副作用：`core:test` 里两条断言依赖中文格式（`百万tokens`、`{p}/{u}起` 不能有空格），改字典时必须先跑测试——本轮就是先挂在这两条上才发现。

3. **桌面壳不复用字典**
   `electron/main.mjs` 是"纯 ESM、零 loader"，`import` 不了 `.ts`。托盘只有十几条文案，就地放一张 `TRAY_TEXT` 表 + `appLang()` 读 `data/settings.json`，每次重建菜单读一次，切语言后下一次重建即生效。

### 9.3 托盘文案的生效时机

`TRAY_TEXT` 在 `projectMenuItems()` / `rebuildTrayMenu()` 里被调用，而菜单只在**状态变化**时重建。所以：

- 切语言后，托盘中文案要等一次状态变化（或重启客户端）才更新
- 窗口标题在 `createWindow()` 时定一次，**必须重启客户端**才变

这是有意的：菜单正打开时重建会闪，不值得为语言切换加一条额外轮询。

### 9.4 明确不做的边界

| 项 | 原因 |
|---|---|
| 「经典 · 表格」布局（~170 处） | 用户决定："先不管，只保证新版布局全英文" |
| 历史审计记录里的动作名 | 存的是当时语言，翻不了也不该翻 |
| 用户数据：资产/项目/账号名、备忘正文、自定义类型名、字段选项值 | 用户输入，翻译会造成"显示与存储不一致" |
| `src/core/test.ts` 断言文案 | 测试内部 |
| `logs/*.log`、`console.*` 输出 | 排障用，固定中文更好读 |

### 9.5 后续若继续推进

- 经典布局：模板结构和新版不同（老表格 + 内联工具栏），建议**直接删**而不是翻，减少两套界面维护成本
- 新语言（如 `ja-JP`）：只需加 `src/shared/i18n/ja/`，`check-i18n` 会强制 key 对齐，`Lang` 类型加一项即可
- 复数：当前只有 `assets.count` 等少数 key 用了 ` | ` 语法，英文单复数已覆盖；新增带数字的文案别手写 `asset(s)`

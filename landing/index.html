Features

More than a password manager

Credentials, assets, project files, an AI assistant and a run workbench — one vault for all of it, entirely on your device.

🔐

Encrypted on-device

The whole vault is written to your local disk as AES-256-GCM ciphertext. Locked, it's unreadable; lose a backup file and whoever finds it gets ciphertext, nothing else.

🤖

A vault that talks

A built-in AI assistant speaks MCP: ask for "the login key of server #7" and it's on your screen. Agents can register assets, check ports and run inspections.

⚡

Run workbench

Register how each local project starts, its dependencies and ports. One click to start and stop — dependencies are torn down with it, containers leave nothing behind.

📜

Full audit trail

Who touched which asset and when, every agent operation — the audit log keeps it all. Sensitive fields reveal on demand and hide again.

Security

Security is the architecture, not a slogan

Three principles baked into the design — not just written in the PR copy.

Keys never touch the cloud

Encryption and decryption happen on your device. There is no "cloud sync copy" and no server that could see your plaintext — because your data simply isn't there.

Open source, auditable

AGPL-3.0, fully public code. Don't take our word for it — build it yourself, or just read the source.

Least privilege

Agents access through allowlists, sensitive fields reveal on demand and re-hide afterwards, and every step lands in the audit log.

Design

How it is put together

One encrypted core, three ways in: the desktop UI, the MCP server your agent talks to, and a local proxy that injects the real secret. Nothing above the core ever holds a plaintext key.

Surface
Desktop UI · Vue 3 + Vite CLI · npm run fk Electron shell
Interfaces
MCP stdio · agent access Model B HTTP proxy · header / Basic / SigV4 SSH bastion · ssh -p 8789 token@127.0.0.1
Core
src/core · vault · schema · proxy · sshproxy · mcp · whitelist · ai-usage
Storage
AES-256-GCM ciphertext on local disk keystore.json · salt + verifier only PBKDF2 · 210 000 iterations

One core, three doors

The UI, the CLI and the MCP server all call src/core. Fix a rule once — allowlists, redaction, audit — and it applies everywhere. There is no second implementation to drift.

The agent gets a token, not a key

Model B hands the agent a short-lived token plus a local proxy address. The real credential is injected server-side and the token dies after use. HTTP, cloud signing and SSH follow the same rule.

Keys live in memory only

The master key is derived from your passphrase with PBKDF2 (210k rounds); the keystore keeps only salt and a verifier. Lock the app and decryption stops — plaintext never reaches the disk.
